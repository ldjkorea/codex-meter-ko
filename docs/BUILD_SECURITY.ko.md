# 빌드·서명·GitHub Actions 전략

PR·main push·수동 실행은 JDK 21 및 SDK 36/37.0에서 기존 회귀 검사, 한국어 리소스·5시간 시계 검사, 폰트 출처 검사, unsigned Release 컴파일과 lint를 실행한다. Action을 전체 커밋 SHA로 고정하고 `contents: read`만 부여하며 checkout의 인증정보 저장을 끈다. `pull_request_target`을 사용하지 않는다.

개인키·비밀번호·토큰·로컬 DB·진단 로그·개발 이력은 공개 소스에서 제외한다. 기존 원본의 암호화된 릴리스 키도 복사하지 않는다. Actions에는 배포 키를 올리지 않고 서명·태그·Release 게시·APK artifact 업로드를 수행하지 않는다.

서명 키 없는 사본의 Gradle Release는 unsigned APK를 만든다. 설치용 파일이 아니다. `build.sh`는 기존 로컬 키와 password가 없으면 실패하며 키를 자동 생성하지 않는다. 유지보수자는 공개 사본을 빌드한 뒤 공개 폴더 밖에 보관된 기존 한국어 키로 로컬 서명한다. 비밀번호는 인수 값이나 로그에 출력하지 않는다. 키를 GitHub Secrets로 옮기는 방식은 사용하지 않는다.

폰트가 수정된 두 AAR는 `licenses/PRETENDARD_PROVENANCE.json`으로 출처·대체 글꼴·해시를 기록한다. 로컬 Maven 저장소로 인증 없는 빌드가 가능하며 검증에서 해시 불일치를 거부한다. 전체 의존성 보안 감사나 모든 과거 취약점 부재를 보증하는 검사는 아니다.

배포 전 APK 서명 지문, 패키지, 버전, minSdk, 포함 라이선스, 금지된 두 폰트 해시 부재를 확인한다. 최종 APK의 SHA-256과 고지 묶음을 제공한다. 저장소와 Release를 게시한 뒤 비로그인 접근 및 자산 다운로드 해시를 다시 확인한다. 같은 패키지·서명·더 높은 versionCode는 업데이트 조건이며 실제 기기 업데이트 성공을 대신 증명하지 않는다.

새 runner의 CI 결과와 로컬 결과는 구분한다. 유지보수자는 릴리스별 검증 기록에 실제 결과를 남긴다. Android 화면·계정 로그인·서비스 조회·OEM 위젯은 실기기 확인이 별도로 필요하다.
